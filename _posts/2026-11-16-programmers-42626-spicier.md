문제 링크: [프로그래머스 코딩테스트 연습 - 더 맵게](https://school.programmers.co.kr/learn/courses/30/lessons/42626)

## 문제 해석

정수 배열에서 가장 작은 두 값을 꺼내 `가장 작은 값 + 두 번째로 작은 값 * 2`로 섞어 다시 넣는 과정을 **모든 값이 K 이상이 될 때까지** 반복하고, 섞은 횟수를 반환하는 문제다. 끝까지 섞어도 K 이상이 안 되면 `-1`을 반환한다. 배열 길이는 최대 1,000,000이다.

- 매번 가장 작은 두 값을 꺼내고 새 값을 넣어야 하므로 **최소 힙**이 맞다. 넣기와 꺼내기가 모두 `O(log N)`이다.
- 매번 정렬하면 `O(N^2 log N)`이라 시간 초과다.

## Review

### 해결 여부

스스로 해결하지 못한 문제다. 최소 힙으로 두 값을 꺼내 섞는 흐름은 맞았지만, 섞는 공식과 끝내는 조건을 잘못 잡았다. 나중에 풀이를 보지 않고 다시 풀어보기 위해 `다시 풀기`로 분류한다.

### 내 풀이 점검

```java
import java.util.*;

/*
scoville를 최소 힙 형태로 정렬 후
	root와 첫 번째 자식 값을 꺼내서 더한 값이 K 미만이라면 더한 값을 다시 넣는다.
    answer++
	힙이 비어버리고 답을 찾지 못한 경우 -1을 반환한다.
*/
class Solution {
    public int solution(int[] scoville, int K) {
        int answer = 0;
       	PriorityQueue<Integer> pq = new PriorityQueue<>();
        for (int s : scoville) {
            pq.offer(s);
        }
        
        while (!pq.isEmpty()) {
            int root = pq.poll();
            int left = pq.poll();
            
            if (root + left >= K) return answer;
            else pq.offer(root + left);
            
            ++answer;
        }
        
        return -1;
    }
}
```

"최소 힙에 넣고, 두 개 꺼내서 섞고, 다시 넣는다"는 흐름은 맞다. 틀린 곳은 섞는 공식, 끝내는 조건, 원소가 하나 남았을 때의 처리다. 문제 예제는 우연히 정답이 나와서 틀린 것을 알아채기 어렵다. 자세한 내용은 아래 "틀린 이유" 단원에서 다룬다.

## 힙과 우선순위 큐

**우선순위 큐는 넣은 순서와 상관없이 우선순위가 가장 높은 원소가 먼저 나오는 큐다.** 힙은 우선순위 큐를 빠르게 구현하는 대표적인 자료구조다. 둘 다 알고리즘이 아니라 자료구조이며, "우선순위 큐라는 동작을 힙이라는 구조로 만든다"고 이해하면 된다.

| 구조 | 먼저 나오는 원소 |
| --- | --- |
| 큐 | 가장 먼저 넣은 원소 |
| 스택 | 가장 나중에 넣은 원소 |
| 우선순위 큐 | 가장 작은 값, 또는 가장 큰 값 |

### 힙의 구조

> 힙은 두 규칙을 지키는 이진 트리다. **완전 이진 트리**라서 위에서 아래로, 왼쪽에서 오른쪽으로 빈칸 없이 채운다. **힙 속성**에 따라 최소 힙은 부모가 항상 자식보다 작거나 같아 루트가 최솟값이고, 최대 힙은 그 반대다.
{: .prompt-tip }

형제끼리는 순서가 정해져 있지 않다. 전체가 정렬된 것이 아니라 "루트가 최솟값"인 것만 보장된다.

완전 이진 트리라서 배열 하나로 저장한다. 인덱스 `i`의 부모는 `(i - 1) / 2`, 자식은 `2i + 1`과 `2i + 2`다.

```text
        1            배열: [1, 3, 8, 5]
       / \           인덱스  0  1  2  3
      3   8
     /
    5
```

### 넣기: 맨 끝에 넣고 위로 올리기

새 원소를 배열 끝에 넣고, 부모보다 작으면 자리를 바꾸는 것을 반복한다. 최소 힙에 5, 3, 8, 1을 차례로 넣으면 다음과 같다.

| 넣은 값 | 과정 | 배열 |
| --- | --- | --- |
| 5 | 그대로 | `[5]` |
| 3 | 부모 5보다 작아서 교환 | `[3, 5]` |
| 8 | 부모 3보다 커서 그대로 | `[3, 5, 8]` |
| 1 | 부모 5와 교환, 다시 부모 3과 교환 | `[1, 3, 8, 5]` |

### 꺼내기: 루트를 빼고 마지막 원소를 내리기

1. 루트를 꺼낸 뒤 배열의 마지막 원소를 루트로 옮긴다. `[1, 3, 8, 5]`에서 1을 꺼내면 `[5, 3, 8]`이 된다.
2. 두 자식 중 더 작은 쪽보다 크면 자리를 바꾸는 것을 반복한다. 자식 3과 8 중 작은 3이 5보다 작아서 교환하면 `[3, 5, 8]`이 된다.

### 시간 복잡도

트리 높이가 `log N`이라서 넣기와 꺼내기 모두 높이만큼만 움직인다.

| 연산 | 힙 | 정렬된 배열 | 정렬 안 된 배열 |
| --- | --- | --- | --- |
| 넣기 | `O(log N)` | `O(N)` | `O(1)` |
| 최솟값 꺼내기 | `O(log N)` | `O(1)` | `O(N)` |
| 최솟값 보기 | `O(1)` | `O(1)` | `O(N)` |

### Java의 PriorityQueue

`PriorityQueue`가 힙으로 만든 우선순위 큐이며 기본은 최소 힙이다. `Queue` 인터페이스를 구현하므로 `offer`, `poll`, `peek`, `isEmpty`, `size`를 그대로 쓴다. 일반 큐의 `poll()`은 먼저 넣은 원소를, `PriorityQueue`의 `poll()`은 가장 작은 원소를 꺼낸다.

```java
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());

minHeap.offer(5);
minHeap.offer(3);
minHeap.offer(8);
minHeap.offer(1);

minHeap.peek();  // 1
minHeap.poll();  // 1을 꺼냄
minHeap.poll();  // 3을 꺼냄
```

> - 출력하거나 순회하면 정렬 순서가 아니라 내부 배열 순서(`[1, 3, 8, 5]`)가 나온다. 정렬된 순서로 받으려면 `poll()`로 하나씩 꺼낸다.
> - 최대 힙을 `(a, b) -> b - a`로 만들면 값이 클 때 뺄셈이 오버플로된다. `Collections.reverseOrder()`나 `(a, b) -> Integer.compare(b, a)`를 쓴다.
> - 배열이나 직접 만든 클래스를 넣으려면 `new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]))`처럼 비교 기준을 넘긴다.
{: .prompt-warning }

### 언제 쓰는가

"매번 가장 작은 것, 또는 가장 큰 것을 꺼내야 하는데 원소가 계속 추가된다"는 조건이 보이면 힙을 떠올린다.

- 상위 K개, K번째 큰 수: 크기 K인 최소 힙을 유지한다.
- 가장 작은 두 개를 합쳐 다시 넣기: 이 문제의 유형이다.
- 작업 스케줄링: 처리 시간이 짧은 작업부터 꺼낸다.
- 다익스트라 최단 경로: 거리가 가장 짧은 정점부터 꺼낸다.

## 최소 힙에서 두 번째로 작은 값 꺼내기

`poll()`을 두 번 부른다. 첫 번째 `poll()`이 최솟값을 꺼내면 힙이 다시 정리되면서 두 번째로 작은 값이 루트로 올라온다.

```java
if (pq.size() >= 2) {
    int first = pq.poll();
    int second = pq.poll();
}
```

`poll()`은 힙이 비어 있으면 `null`을 반환하고, 이를 `int`에 넣으면 `NullPointerException`이 난다. 원소가 두 개 이상인지 먼저 확인한다.

| 단계 | 배열 | 루트 |
| --- | --- | --- |
| 처음 | `[1, 3, 8, 5]` | 1 |
| 첫 번째 `poll()`, 1을 꺼냄 | `[3, 5, 8]` | 3 |
| 두 번째 `poll()`, 3을 꺼냄 | `[5, 8]` | 5 |

- **두 번째로 작은 값은 루트의 두 자식 중 더 작은 쪽이다.** 루트가 아닌 노드는 모두 자기보다 작거나 같은 부모를 가지는데, 두 번째로 작은 값보다 작은 값은 루트 하나뿐이므로 그 부모는 루트다. 형제끼리는 순서가 없으므로 "첫 번째 자식"이 아니라 "더 작은 자식"이다.
- `PriorityQueue`는 루트를 보는 `peek()`만 제공하고 자식에 직접 접근하는 메서드는 없다. 두 번째 값을 얻는 방법은 꺼내는 것뿐이다.
- 꺼내지 않고 보기만 하려면 하나를 `poll()`로 꺼내 다음 값을 `peek()`으로 본 뒤 다시 `offer()`한다.
- 최솟값이 중복이면 두 번째 `poll()`도 같은 값을 반환한다.

## 틀린 이유

### 섞는 공식이 다르다

공식은 `가장 작은 값 + 두 번째로 작은 값 * 2`인데, 코드는 두 값을 그냥 더한다.

```java
pq.offer(root + left);          // 내 코드
pq.offer(root + left * 2);      // 문제의 공식
```

### 끝내는 조건이 다르다

목표는 **모든 값**이 K 이상이 되는 것인데, 코드는 "방금 섞은 값이 K 이상인지"를 보고 바로 끝낸다.

- **다른 값이 아직 K 미만일 수 있다.** 방금 섞은 값이 K 이상이어도 힙에 K 미만인 값이 남아 있으면 더 섞어야 한다.
- **방금 섞은 횟수를 세지 않고 반환한다.** `++answer`보다 `return`이 먼저라서 마지막 1회가 빠진다.
- **처음부터 모두 K 이상이면 섞으면 안 된다.** 코드는 확인도 하기 전에 무조건 한 번 섞는다.

> 모든 값이 K 이상인지는 최소 힙의 루트만 보면 된다. 가장 작은 값이 K 이상이면 나머지도 전부 K 이상이다. 그래서 섞기 전에 `pq.peek() < K`를 확인한다.
{: .prompt-info }

### 원소가 하나 남으면 에러가 난다

`while (!pq.isEmpty())`는 원소가 하나만 남아도 반복한다. 그 상태에서 `poll()`을 두 번 하면 두 번째가 `null`을 반환하고, `int`에 넣는 순간 `NullPointerException`이 난다. 하나 남았는데 아직 K 미만이면 더 섞을 수 없으므로 `-1`을 반환해야 한다.

### 실행 결과

직접 만든 입력으로 내 코드와 고친 코드를 실행한 결과다.

| 입력 | K | 내 코드 | 정답 | 틀린 원인 |
| --- | --- | --- | --- | --- |
| `[1, 1, 1, 100]` | 3 | 1 | 2 | 공식, 끝내는 조건 |
| `[0, 0, 5]` | 1 | 1 | 2 | 공식, 끝내는 조건 |
| `[1, 8]` | 7 | 0 | 1 | 마지막 섞기를 세지 않음 |
| `[1, 2]` | 100 | 에러 | -1 | 원소 하나 남을 때 처리 없음 |

## 풀이 — PriorityQueue

### 풀이 방법

1. 모든 값을 최소 힙에 넣는다.
2. 원소가 두 개 이상이고 가장 작은 값이 K 미만인 동안, 두 값을 꺼내 섞어 다시 넣고 횟수를 센다.
3. 반복이 끝나면 루트가 K 이상이면 횟수를, 아니면 `-1`을 반환한다.

### Java 코드

```java
import java.util.*;

class Solution {
    public int solution(int[] scoville, int K) {
        PriorityQueue<Integer> pq = new PriorityQueue<>();
        for (int s : scoville) {
            pq.offer(s);
        }

        int answer = 0;
        while (pq.size() >= 2 && pq.peek() < K) {
            int first = pq.poll();
            int second = pq.poll();
            pq.offer(first + second * 2);
            answer++;
        }

        return pq.peek() >= K ? answer : -1;
    }
}
```

- `pq.peek() < K`: 가장 작은 값이 아직 K 미만일 때만 섞는다. 처음부터 모두 K 이상이면 한 번도 섞지 않고 `0`을 반환한다.
- `pq.size() >= 2`: 섞을 두 개가 있을 때만 반복해서 `null`을 꺼내지 않는다.

### 동작 예시

`[1, 1, 1, 100]`, `K = 3`이다.

| 반복 | 꺼낸 두 값 | 섞은 값 | 힙 | 횟수 |
| --- | --- | --- | --- | --- |
| 시작 | - | - | `[1, 1, 1, 100]` | 0 |
| 1 | 1, 1 | `1 + 1 * 2 = 3` | `[1, 3, 100]` | 1 |
| 2 | 1, 3 | `1 + 3 * 2 = 7` | `[7, 100]` | 2 |
| 종료 | 루트 7이 3 이상 | - | - | 2 반환 |

### 시간 및 공간 복잡도

- 시간 복잡도: **`O(N log N)`** — 힙 구성에 `O(N log N)`, 섞기 1회에 `O(log N)`이고 섞기는 최대 `N - 1`번이다.
- 추가 공간 복잡도: **`O(N)`** — 모든 값을 힙에 저장한다.

## 다시 풀 때 생각할 점

- 공식은 문제에서 다시 확인한다. 흐름이 맞아도 공식 하나가 틀리면 전부 틀린다.
- 멈추는 조건은 섞은 결과가 아니라 힙 전체 기준이다. 최소 힙에서는 루트(`peek()`)만 보면 된다.
- `poll()`을 두 번 하기 전에 원소가 두 개 이상인지 확인한다. `while (!pq.isEmpty())`는 하나 남았을 때를 막지 못한다.
- `return`과 카운트 증가의 순서를 확인한다.
- 두 번째로 작은 값은 루트의 "첫 번째 자식"이 아니라 "더 작은 자식"이고, `PriorityQueue`에서는 `poll()`을 두 번 해서 얻는다.
